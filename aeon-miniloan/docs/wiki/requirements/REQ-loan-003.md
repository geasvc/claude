# REQ-loan-003

## เป้าหมาย
พิจารณาใบสมัครที่ประเมินแล้วบนเหตุผลรายเกณฑ์ที่ระบบให้ แล้วอนุมัติหรือปฏิเสธพร้อมบันทึกร่องรอย

**actor:** Loan Officer · **ความสำคัญ:** high · **มีหน้าจอ:** ใช่

## คุณค่าทางธุรกิจ
มีคนรับผิดชอบการตัดสินใจทุกใบ และใบที่ปฏิเสธแล้วย้อนกลับมาอนุมัติไม่ได้

## กฎที่ยังใช้อยู่

| กฎ | ชนิด | ข้อความ | ตัวอย่าง |
|---|---|---|---|
| [BR-loan-009@v1](../rules/BR-loan-009@v1.md) | invariant | อนุมัติได้เฉพาะใบสมัครที่อยู่ในสถานะ UnderReview เท่านั้น เมื่ออนุมัติแล้วสถานะเปลี่ยนเป็น Approved พร้อมบันทึกผู้อนุมัติและเวลา | 🔴 0 |
| [BR-loan-010@v1](../rules/BR-loan-010@v1.md) | invariant | ปฏิเสธใบสมัครที่อยู่ในสถานะ UnderReview หรือได้ Band C ได้โดยต้องระบุเหตุผล แล้วสถานะเปลี่ยนเป็น Rejected ซึ่งเป็นสถานะสุดท้าย · ใบที่ Rejected แล้ว ถ้าพยายามอนุมัติ ระบบต้องปฏิเสธการกระทำ (invalid transition) | 🔴 0 |
| [BR-loan-011@v1](../rules/BR-loan-011@v1.md) | policy | เมื่อเจ้าหน้าที่เปิดดูใบสมัครที่มี CreditAssessment ต้องเห็นรายการเกณฑ์ที่ผ่านและไม่ผ่านเป็นรายข้อ พร้อมวงเงินสูงสุดตาม BR-loan-006@v1 | 🔴 0 |
| [BR-loan-025@v1](../rules/BR-loan-025@v1.md) | invariant | ใบสมัครแต่ละใบมีเจ้าหน้าที่ผู้รับผิดชอบที่ถูกมอบหมาย (assign) และมีผู้สำรอง · อนุมัติหรือปฏิเสธใบสมัครได้เฉพาะเจ้าหน้าที่ที่ถูกมอบหมายใบนั้น หรือผู้สำรองของใบนั้นเท่านั้น · เจ้าหน้าที่คนอื่นแม้จะเป็น Loan Officer ก็ทำไม่ได้ | 🔴 0 |
| [BR-loan-026@v1](../rules/BR-loan-026@v1.md) | policy | role ที่มีสิทธิ์อนุมัติหรือปฏิเสธใบสมัครเป็นค่าที่ตั้งได้ ไม่ฝังตายในโค้ด — เปลี่ยน role ผู้อนุมัติได้โดยไม่ต้องแก้โปรแกรม · การตั้งค่านี้ต้องไม่ทำให้ Applicant ได้สิทธิ์ที่ BR-loan-024@v1 ห้ามไว้ | 🔴 0 |
| [BR-loan-027@v1](../rules/BR-loan-027@v1.md) | policy | ใบสมัครที่เข้าสถานะ UnderReview เข้าคิวใบสมัครรอพิจารณาเป็นค่าเริ่มต้น โดยยังไม่ผูกกับเจ้าหน้าที่คนใด · Loan Officer หยิบใบจากคิวมาเป็นผู้รับผิดชอบของตัวเองได้เอง (self-assign) และเปลี่ยนมือมอบหมายใหม่ทีหลังได้ · การเข้าสถานะ UnderReview ต้องไม่ถูกบล็อกเพราะยังไม่มีผู้รับผิดชอบ | 🔴 0 |
