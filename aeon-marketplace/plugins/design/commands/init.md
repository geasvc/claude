# /design:init — ตั้งต้นเฟสออกแบบ

คำสั่งแรกของ Phase 2 **ต้องรันก่อนคำสั่งอื่นทุกตัว**

หน้าที่มีสองอย่างเท่านั้น คือ **ตรวจว่าของจาก `req` ครบไหม** กับ **สร้าง `design.state.json`**
ไม่ออกแบบอะไรทั้งสิ้น ยังไม่แตะ requirement แม้แต่ข้อเดียว

## ของที่อ่านเข้ามา

อ่าน `spec.json` ที่ `req` เขียนไว้ **ไฟล์เดียว** ผ่าน `scripts/req-contract.mjs`

> **ทำไมไม่ใช่ `requirements.json` ตามสเปก §3.1**
> §3.1 เขียนสัญญาไว้เป็นห้าไฟล์แยกกัน แต่ `req` v0.3.0 ผลิตไฟล์เดียวคือ `spec.json`
> ถ้ายึดตามตัวอักษร คำสั่งนี้จะ halt ทุกโปรเจกต์จริง — ไม่มีทางสำเร็จได้แม้แต่ครั้งเดียว
> เจ้าของเคาะเมื่อ 2026-08-20 ให้อ่าน `spec.json` แล้วแก้ §3.1 ให้ตรงความจริง
> เจตนาเดิมของ §3.1 (ห้ามผูกกับไส้ในของ plugin อื่น) ยังอยู่ครบ เพราะ `spec.json` มี `$id`
> และ `meta.schema_version` กำกับ — ไฟล์ที่มี schema และเลขเวอร์ชันคือสัญญา ไม่ใช่ไส้ใน

## ขั้นตอน

1. **รันแบบยังไม่เขียน** (ค่าเริ่มต้นคือไม่เขียนอะไรเลย):
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --root .
   ```
   ถ้าโปรเจกต์ตั้งชื่อไดเรกทอรีสถานะเอง ให้ใส่ `--state-dir <ชื่อ>` หรือใช้ `$AEON_STATE_DIR`
   **ห้ามไปเดาหาว่า spec.json อยู่ไหน** ที่อยู่ถูกประกาศไว้ ไม่ใช่ค้นเจอ

2. **อ่านผลให้เจ้าของฟังเป็นภาษาไทย** ตามนี้

   **ถ้า exit 2 — หยุด ห้ามเดาแล้วทำต่อ**
   - `MISSING spec.json` → `req` ยังไม่ได้ทำงานในโปรเจกต์นี้ **ยกพาธที่มันหาไปพูดตรง ๆ** แล้วบอกให้ไปรัน `/req:capture` ก่อน
   - `MISSING glossary[]` / `requirements[]` → มีไฟล์แต่ของข้างในไม่ครบ ให้กลับไปที่ `req`
   - `MALFORMED` → ไฟล์ผิดรูปจาก schema ให้บอกว่าผิดตรงไหน **ห้ามซ่อมไฟล์ของ `req` ให้** เพราะนี่คือของที่ plugin อื่นเป็นเจ้าของ (§5.4 W1)

   **ถ้า exit 0** — รายงานตัวเลขที่มันพิมพ์ออกมา: requirements กี่ข้อ · glossary กี่คำ · schema เวอร์ชันอะไร

3. **บอกของที่ `req` ไม่มีให้ ทุกครั้ง ไม่ใช่ข้ามไปเงียบ ๆ**
   - `stakeholders` — **`req` ไม่มีแนวคิดนี้เลย** แต่ §13.3 A4 กับ V23 บังคับว่า role ทุกตัวใน `rbac.json`
     ต้องมาจาก stakeholder ที่ `req` บันทึกไว้ → จะกลายเป็น **error ตอน `/design:rbac`**
     สคริปต์บันทึกไว้เป็น `Q-STAKEHOLDERS` ที่ `blocks: [rbac]` ให้แล้ว **เจ้าของต้องตัดสินก่อนถึงขั้นนั้น**
   - `okr` — ไม่มีเหมือนกัน แต่เป็นแค่ recommended ไม่บล็อกอะไร

4. **หยุดขออนุมัติ 🛑** ให้เจ้าของดูผลก่อน ยังไม่เขียนอะไร

5. อนุมัติแล้วค่อยเขียนจริง:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --root . --write
   ```
   สร้าง `<state-dir>/design/design.state.json` + โฟลเดอร์ `modules/`

6. บอกคำสั่งถัดไปคือ `/design:overview` **แต่ห้ามรันเอง** แล้วหยุด 🛑

## กติกาที่คำสั่งนี้ต้องไม่ละเมิด

- **รันซ้ำได้ผลเท่าเดิม** — ของที่ `done` แล้วต้องไม่ถูกรีเซ็ต ไม่มี step ซ้ำ ไม่มีคำถามซ้ำ
  (พิสูจน์แล้วในขั้นตอนสร้าง: เขียนซ้ำสองรอบ `overview` ที่เป็น done พร้อม attempts 3 ยังอยู่ครบ)
- **ห้ามเขียนไฟล์ใด ๆ ของ `req`** — `spec.json` มีเจ้าของแล้ว เขียนทับเมื่อไหร่ของเขาหายเงียบ
- **ห้ามตอบว่า "เรียบร้อย" ก่อนไฟล์ลงดิสก์จริง** — เขียนก่อน แล้วค่อยพูด

## ตรวจตัวสคริปต์เอง

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/clean"                        # ต้อง exit 0
node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/dirty" --state-dir .notaeon   # ต้อง exit 2
node "${CLAUDE_PLUGIN_ROOT}/scripts/init.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/empty"                        # ต้อง exit 2
```

สัญญาของแต่ละ fixture อยู่ที่ `scripts/fixtures/EXPECTED.md`
