# req — เก็บ requirement → กฎ (Phase 1)

**ตอบคำถามเดียวตลอดเวลา: "กฎข้อไหนยังไม่มีใครพิสูจน์"** — วัดจากไฟล์ ไม่ใช่ให้ AI ให้คะแนน

**ทุกคำสั่งจบด้วยการหยุดรอพี่ปูอนุมัติ** ไม่มีตัวไหนไหลไปขั้นถัดไปเอง · 👁 = อ่านอย่างเดียว ไม่เขียนไฟล์

## คำสั่งที่ใช้ได้ตอนนี้ (8 ตัว)

### `/req:capture [module]` — ประตูเดียวของ input ดิบ

รับ**ข้อความที่พิมพ์ + ไฟล์แนบหลายไฟล์พร้อมกัน** ในครั้งเดียว · 1 ชิ้น = 1 แหล่ง (`SRC-xxx`)

```
/req:capture job
แล้วแนบ: TOR.docx · ตารางราคา.xlsx · screenshot Line 3 รูป · export งานจริง 500 แถว.csv
พร้อมพิมพ์บอกเพิ่มว่า "งานขนส่งเดินจาก INIT ถึง COMPLETE ถอยได้เฉพาะ admin"
```

**ระบบจะ:** เรียงรายการ input ให้ดูก่อน → เอาไฟล์เข้า `docs/` → อ่านไฟล์ (Excel อ่าน**สูตร**ด้วย)
→ ร่างคำศัพท์+กฎ → **ถามยืนยันทีละ 3 ข้อ** → เขียน `spec.json` + เอกสาร `.md` → 🛑 หยุด

**ถ้ามีไฟล์ข้อมูลจริงของลูกค้าปนมา** ระบบจะแยกมันออกจากเอกสาร — มันเป็น**หลักฐานว่าเลขที่ถูกคือเท่าไหร่**
ไม่ใช่แหล่งของกฎ · **ระบบจะไม่ร่างกฎจากมัน** ทำได้แค่ตั้งข้อสงสัยพร้อมตัวหาร (*"47 แถวจาก 500 …"*) แล้วถาม
และจะ **ถามเรื่องปิดบังข้อมูลส่วนบุคคลก่อนเขียนไฟล์เสมอ** เพราะ `docs/` อยู่ใต้ git — เขียนแล้วอยู่ใน history ตลอดไป
รายละเอียดอยู่ใน [`USER-GUIDE.md`](../USER-GUIDE.md) หัวข้อ *"ข้อมูลตัวอย่างจากลูกค้า"*

**เรียกโดยไม่แนบอะไรเลยก็ได้** = โหมดซ่อมเอกสาร (พี่ปูแก้ `spec.json` เองแล้วเอกสารล้าสมัย)

### `/req:ask [หมวด]` — ยิงคำถามทีละ 3 ข้อ · **กรอบก่อน แล้วค่อยกฎ**

```
/req:ask                 → ยังไม่เคยตั้งกรอบโมดูลนี้ → ยิงชั้น 1 ให้ก่อน
                           ตั้งกรอบแล้ว → เลือกหมวดกฎที่ยังไม่เคยถามให้เอง
/req:ask calculation     → บังคับหมวด (ระบุได้ทั้งสองชั้น)
```

**ชั้น 1 · กรอบ — ยิงครั้งเดียวต่อโมดูล 2 รอบ (6 ข้อ)** ตรงกับขั้น 1–4 ของ pipeline
`เป้าหมายปลายทาง` · `ขอบเขต` · `ผู้เกี่ยวข้อง` · `ศัพท์กลาง`
> รอบ A — สำเร็จแปลว่าอะไร และรอบนี้ทำถึงไหน · รอบ B — ใครแตะบ้าง และเรียกว่าอะไร
> **ต้องมี `/req:capture` มาก่อน** เพราะการ์ดแดงของชั้นนี้ต้องอ้าง `SRC-xxx` (ยังไม่มีกฎให้อ้าง)
> ชั้นนี้เขียนได้แค่ เป้าหมาย · ขอบเขต(ในเนื้อความ) · actor · คำศัพท์ · การ์ดแดง — **ไม่ร่างกฎเอง**
> ⚠️ **ชั้น 1 ยังเป็นร่าง** — คำถามมาจากการ์ด pipeline ยังไม่ผ่านเกณฑ์ "เคยงัดกฎที่ลืมได้จริงจากงานลูกค้าจริง"

**ชั้น 2 · กฎ — ยิงซ้ำได้เรื่อยๆ ต่อ REQ** ตรงกับขั้น 5–7 · **10 หมวด:**
สิทธิ์ · การย้อนกลับ · จุดแช่แข็ง · ผู้อนุมัติ · ร่องรอย · การคำนวณ · เวลา/เวอร์ชัน · ขอบเขตข้อมูล · ระบบภายนอก · การยิงซ้ำ

มี **⭐ เลือกไว้ให้แล้ว** กดยืนยันทีเดียวจบ — แต่ดาวของสองชั้นคนละความหมาย
**ชั้น 2** = นิสัยการออกแบบของพี่ปูเอง · **ชั้น 1** = สิ่งที่อ่านได้จากอินพุต พร้อมอ้าง `SRC` + ตำแหน่ง
(เป้าหมายของโมดูลไม่ใช่นิสัยที่ซ้ำข้ามโปรเจกต์ ถ้าอินพุตไม่ได้บอก จะถามแบบไม่มีดาวและบอกว่าไม่มี)

ทุกข้อมีตัวเลือก **"ยังไม่แน่ใจ / ต้องถามลูกค้า"** → เลือกแล้วเกิด **การ์ดแดง 🛑**

**สั่งซ้ำได้เรื่อยๆ** ระบบจำว่าถามหมวดไหนไปแล้ว และหยุดเองเมื่อครบ

### `/req:calc <BR-id>` — ตรึงวิธีคิดเลขของกฎ (สัญญาการคำนวณ)

```
/req:calc BR-job-016
→ ถามทีละหัวข้อ 7 อย่าง แล้วได้ CALC-xxx ผูกกับกฎเวอร์ชันนั้น
```

**กฎบอกว่าต้องเป็นอะไร · สัญญาบอกว่าคิดเลขยังไง** — สองคนเขียนโค้ดตามกฎเดียวกันได้ผลต่างกันหลักสตางค์
ทุกครั้งที่เกิดเรื่องนี้ สาวกลับได้เสมอว่ามีหัวข้อใดหัวข้อหนึ่งข้างล่างที่ไม่มีใครเขียนไว้

| ถาม | ถ้าไม่ถามจะเจอ |
|---|---|
| **สูตร** ตรงตัวที่ลูกค้าพูด | ต่างคนต่างจำสูตรคนละแบบ |
| **input** ชื่อ + ชนิด (`money(2)` `rate(10)` `int`) | ปนชนิดข้อมูล ตัดทศนิยมทิ้งเงียบ ๆ |
| **ชนิดตัวเลข** — `decimal` หรือ `integer` | **ห้าม float** · float เก็บ 0.1 ไม่ได้ เงินเพี้ยนแล้วแก้ปลายทางไม่ได้ |
| **วิธีปัด** — `HALF_UP` ฯลฯ | .NET ปัดครึ่งไปเลขคู่เป็นค่าเริ่มต้น คนละผลกับที่คนไทยเข้าใจ |
| **ปัดตรงไหน** ไม่ใช่แค่ปัดยังไง | ปัดทุกงวด vs ปัดครั้งเดียวตอนท้าย ต่างกันหลักบาท |
| **เศษที่เหลือ** ใครรับ | ยอดค้าง 0.03 บาทที่ไม่มีวันปิด |
| **ขอบเขต** — `n = 0` · `r = 0` · ค่าต่ำสุด | หารด้วยศูนย์ที่ไปโผล่ตอนขึ้นระบบจริง |

**คำสั่งนี้ไม่คิดเลขให้** — มันเก็บ*สัญญา* ส่วนการกดเลขจริงแล้วให้คนยืนยันเป็นงานของ `/req:golden` (หัวข้อถัดไป)
ตอบ *"ยังไม่แน่ใจ"* ข้อไหน → **การ์ดแดง 🛑** · ข้อที่ต้องเห็น entity ก่อน (เช่น `decimal(p,s)`) → **คิวส่งต่อ ⏭**

### `/req:example <BR-id>` — แตกตัวอย่างที่พิสูจน์กฎ

```
/req:example BR-job-009
→ ได้ 2-4 ตัวอย่างแบบ given-when-then ครอบ happy / exception / boundary
```

**`then` ต้องเป็นข้อความไทยตรงตัวที่ user เห็นจริง** ไม่ใช่ "แสดง error"
(เคยละข้อนี้แล้ว QA ต้องเผาไปหนึ่งรอบเต็ม)

### `/req:golden <BR-id|CALC-id>` — เลขเฉลยที่รันจริงแล้วคนเซ็น

```
/req:golden BR-job-016
→ เขียนสคริปต์ → รัน → เอาผลมาให้ดู → พี่ปูเซ็น → GD-xxx
```

**คำสั่งเดียวในชุดที่เป็นชนิด "พิสูจน์"** — ตัวอื่นเก็บสิ่งที่คนพูด ตัวนี้ผลิตตัวเลขแล้วถามว่าถูกไหม
สูตรที่ทุกคนเห็นด้วยแล้ว **ไม่เท่ากับ**ตัวเลขที่มีใครตรวจแล้ว · งวดสุดท้ายที่ออกมา 9,504.**43** รู้ได้ตอนกดเลขเท่านั้น

**4 ข้อที่ห้ามละเมิด:**

1. **ห้ามคิดเลขในหัว** ต้องเขียนสคริปต์ รัน แล้วโชว์ทั้งสคริปต์และผล · สคริปต์เก็บไว้ที่ `<state-dir>/golden/` รันซ้ำได้
2. **ตัวเลขเป็นแค่ข้อเสนอจนกว่าคนจะเซ็น** — `verified_by` ว่างอยู่ = สถานะที่ถูกต้อง ไม่ใช่ความล้มเหลว (check #13 แค่เตือน ⚠️ ไม่บล็อก)
3. **ถ้าเลขไม่ตรงกับสัญญา → แก้สัญญา ย้อนไป `/req:calc`** · **ห้ามแก้เลขเฉลยให้เข้ากับสูตร** เพราะนั่นคือการทำลายตัวตรวจอิสระตัวเดียวที่ Phase 1 มี
4. **ข้อมูลลูกค้าเป็น input ไม่ใช่กฎ** — เอาแถวจริงมาป้อน แล้ว **diff ผลของเรากับผลของลูกค้า** · ตรงไหนไม่ตรง = **ตรงนั้นมีกฎที่ยังไม่มีใครบอก** ซึ่งเป็นของมีค่าที่สุดที่ทั้ง plugin นี้ผลิตได้

### `/req:change <BR-id|CALC-id>` — เปลี่ยนกฎที่มีอยู่แล้วให้ถูกกติกา

```
/req:change BR-job-011
→ เห็นข้อความเดิม vs ใหม่คู่กัน → บังคับกรอกเหตุผล → เกิด @v2 + CHG-xxx
```

**นี่คือทางเดียวที่จะเกิด `@v(n+1)`** ไม่ใช่เพราะสะดวก แต่เพราะถ้า `/req:capture` ทำเองได้ด้วย
จะมี**สองเส้นทางที่สร้างของชิ้นเดียวกัน** ซึ่งเป็นสิ่งที่ระบบนี้ห้ามไว้ตรง ๆ

**สิ่งที่มันบังคับ:**

| บังคับ | ทำไม |
|---|---|
| **ต้องกรอกเหตุผล** ไม่กรอกไม่ไปต่อ | ตัวตรวจ #6 แดงอยู่ดี · ถามตอนที่บทสนทนายังเปิดอยู่ได้คำตอบดีกว่า |
| **ถามตัวอย่างทีละตัว** ว่ายังพิสูจน์ข้อความใหม่ได้ไหม | ตัวอย่างที่ยกข้ามมาเฉย ๆ = coverage สวยแต่ไม่มีอะไรถูกพิสูจน์ · **ตอบว่าไม่ได้แล้ว → coverage ตก ซึ่งถูกต้อง** |
| **บอกรัศมีผลกระทบก่อนเขียน** | `CALC` ที่ผูกต้องขึ้นเวอร์ชันตาม · `GD` ที่คำนวณจากสัญญาเก่า **ใช้ไม่ได้แล้ว ต้องรัน `/req:golden` ใหม่** |
| **`effective_from` อยู่บนโหนดเวอร์ชัน** ไม่ใช่แค่บน `CHG` | ตอบคำถาม *"ตอนใบสมัครใบนี้ถูกสร้าง กฎคือเวอร์ชันไหน"* ได้โดยไม่ต้องเดินย้อนผ่าน `CHG` |

**`CHG-xxx` คือบันทึกการเปลี่ยนหนึ่งครั้ง** — เก็บเป็นโหนดแยกเพราะ**การเปลี่ยนครั้งเดียวขยับหลายโหนดพร้อมกัน**
ลดดอกเบี้ยทีเดียวขยับทั้งกฎ ทั้งสัญญาการคำนวณ และทำให้เลขเฉลยตาย · เก็บเหตุผลไว้ในแต่ละโหนดจะถูกก๊อป 3 ที่
แล้วไม่มีใครตอบได้ว่า *"รอบวันที่ 13 แก้อะไรไปบ้าง ใครสั่ง มาจากเอกสารไหน"* ซึ่งเป็นคำถามที่ลูกค้าถามจริง

> **`/req:capture` ตรวจให้เองแล้วว่าอันไหนเป็น "การเปลี่ยน" ไม่ใช่ "กฎใหม่"** — เจอแล้วจะ**แช่แข็ง REQ นั้น
> ไม่เขียนอะไรลงไฟล์เลย** แล้วบอกให้พิมพ์คำสั่งนี้ · มันจะไม่รันให้เอง

### `/req:check [--cp2]` 👁 — สถานะ + ด่าน CP1

```
/req:check          → อะไรค้าง + ผ่าน CP1 ไหม
/req:check --cp2    → ดูเฉพาะคิวส่งต่อ (Phase 2)
```

รายงาน 4 หัวข้อ: 🛑 บล็อก CP1 · ⏭ บล็อก CP2 · ⚠️ เตือนไม่บล็อก · 📊 สถานะรวม

> **ตัวตรวจเขียว ≠ อนุมัติแล้ว** — CP1 พี่ปูเป็นคนเซ็น ตัวตรวจแค่บอกว่าถามได้แล้ว

```
# เมื่อลูกค้าเปลี่ยนใจทีหลัง — ไม่ใช่ลำดับปกติ แต่เกิดบ่อยที่สุด
/req:capture         เอาของใหม่เข้า → ระบบบอกเองว่า "นี่คือการเปลี่ยน" แล้วแช่แข็ง REQ  🛑
/req:change BR-xxx   ยกเวอร์ชันให้ถูกกติกา + บันทึก CHG                              🛑
```

## 3 อย่างที่ควรรู้

**1. การ์ดแดง 🛑 กับ คิวส่งต่อ ⏭ คนละเรื่อง**

| | การ์ดแดง `Q-xxx` | คิวส่งต่อ `DQ-xxx` |
|---|---|---|
| คือ | **ไม่รู้คำตอบ** ต้องถามลูกค้า | **รู้ว่าจะตอบยังไง** แต่ต้องเห็น entity ก่อน |
| ตัวอย่าง | "ใครเป็นคนอนุมัติ" | "ปัดกี่ตำแหน่ง / `decimal(p,s)` เท่าไหร่" |
| บล็อก | **จบ Phase 1 ไม่ได้** | บล็อก Phase 2 — Phase 1 ผ่านได้ตามปกติ |

**2. คำศัพท์ต้องนิ่งก่อนถามกฎ**
ลูกค้าพูดว่า "งาน" → หมายถึง `Job` (ทั้งใบ) หรือ `Trip` (เที่ยววิ่ง)?
ถ้าไม่นิยามก่อน กฎทุกข้อที่พูดถึง "งาน" จะกำกวมตั้งแต่เกิด — ระบบเก็บไว้ใน `glossary`
ตอนนี้มีที่ถามเป็นเรื่องเป็นราวแล้ว: หมวด `ศัพท์กลาง` ของชั้น 1 ถามเป็น**คู่คำ** ("ก กับ ข อันเดียวกันไหม")
เพราะคนนิยามคำเดียวได้เสมอ แต่ตอบไม่ได้เสมอว่าสองคำเป็นสิ่งเดียวกัน — และคู่คำนี่แหละที่บอกว่ากำลังจะเกิดคลาสซ้ำ

**3. Excel หลอกที่สุด**
กฎมักซ่อนอยู่ใน**สูตร** ไม่ใช่ค่าในเซลล์ — เซลล์แสดง `930` แต่สูตรคือ `=IF(B2>1000, B2*0.93, B2)`
= *"เกิน 1,000 ลด 7%"* · ระบบอ่านสูตรด้วยเสมอ
