# /design:status 👁 — สถานะเฟสออกแบบ

อ่านอย่างเดียว **ไม่เขียนไฟล์ใด ๆ แม้แต่ไฟล์เดียว**

คำสั่งนี้คือ **เงื่อนไขจบของลูป** — เป็นตัวตอบว่า "เสร็จหรือยัง" และคำตอบนั้น**ห้ามมาจากโมเดล**

> §8.2 เขียนข้อนี้ละเอียดกว่าคำสั่งอื่นทุกตัว เพราะโมเดลที่ตัดสินงานของตัวเองว่าเสร็จแล้ว
> คือความพังที่ทั้งดีไซน์นี้ตั้งใจหนี · ผลจึงมาจาก **exit code ของสคริปต์** เท่านั้น

## ขั้นตอน

1. รัน:
   ```
   node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root .
   ```

2. **รายงานให้เจ้าของฟังก่อน ห้ามเริ่มงานใหม่** (§8.2 ข้อ 4 บังคับตรงตัว)
   บอกสามอย่าง: ทำอะไรไปแล้ว · ติดอะไร · คำสั่งถัดไปคืออะไร

3. **หยุด 🛑** ให้เจ้าของสั่งเองว่าจะเดินต่อไหม

## รหัสจบ

| รหัส | ความหมาย | ทำอะไรต่อ |
|---|---|---|
| `0` | เสร็จครบและผ่านการตรวจ | ไม่มีอะไรต้องทำ |
| `1` | ยังมีงานเหลือ **และมีอย่างน้อยหนึ่ง step ที่รันได้เลย** | รันคำสั่งที่มันบอก |
| `2` | ติดบล็อก **ไม่มีอะไรรันได้เลย** | ต้องมีคนตัดสินใจก่อน |

> **`2` ไม่ได้แปลว่า "มีบางอย่างติด"** — ถ้า step ไกล ๆ ติดคำถามอยู่ แต่อีกสามตัวรันได้เลย คำตอบที่ซื่อสัตย์คือ `1`
> `2` สงวนไว้สำหรับกรณีที่ **ไม่มีอะไรเดินต่อได้จริง ๆ** · รายงาน `2` ทั้งที่ยังมีงานทำได้ = สอนให้ทุกคนเลิกสนใจ `2`

**ผลลัพธ์บอกคำสั่งถัดไปเสมอ** ไม่ว่ารหัสจะเป็นอะไร — ถ้าไม่มีคำสั่งไหนรันได้ มันจะบอกว่า**คนต้องทำอะไร** แทน

## สามเหตุผลที่ทำให้ `0` ยากกว่าที่คิด

`0` ไม่ได้แปลว่า "ทุก step เขียนว่า done" เพราะสองข้อนี้บังคับไว้ และมีเหตุผลของมัน

| กติกา | ผล |
|---|---|
| §9.2 กติกา 6 | **ห้ามคืน `0` ขณะที่ยังมีของ `stale`** — requirement เปลี่ยนแล้วแต่ยังไม่มีใครแก้ตาม |
| §19.3 | **ห้ามคืน `0` ขณะที่ยังมีคำถามเปิดที่ `blocks` ไม่ว่าง** — คำถามที่ยังไม่มีคำตอบคือของที่ยังไม่จบ |

**ไฟเขียวที่ไม่จริง แย่กว่าไฟแดง** เพราะไฟแดงทำให้คนหยุดดู ส่วนไฟเขียวปลอมทำให้คนส่งมอบ

## ตัวกันลูปวน

`attempts` เกิน **3** ครั้งบน step เดียวกัน → นับเป็น `blocked` และรอคน (§8.2)

เหตุผล: agent ที่ลองใหม่เรื่อย ๆ กับปัญหาที่ตัวเองแก้ไม่ได้ จะเผาเวลาไปเรื่อย ๆ โดยไม่มีใครรู้ว่ามันติด

## ข้อจำกัดที่รู้อยู่ ยังไม่ปิด

- **`wiki-index.json` ยังไม่มีคำสั่งไหนสร้าง** — §8.2 ข้อ 2 บอกให้ agent นำทางผ่าน index ไม่ใช่ไล่อ่านทุกไฟล์ · สคริปต์รายงานว่าไม่มี แทนที่จะเงียบ
- **คำถามที่เปิดค้างยังไม่มีทางกลับไปหา `req`** — D16 (back-channel) ยังไม่เคาะ · ตอนนี้คำตอบต้องให้**คนถือกลับไป** ไม่ใช่คำสั่ง · สคริปต์พิมพ์เตือนข้อนี้ทุกครั้งที่มีคำถามค้าง

## ตรวจตัวสคริปต์เอง

```
node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/status-work"      # exit 1 · มี step รันได้
node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/status-blocked"   # exit 2 · attempts 4 ชน loop guard
node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/status-done"      # exit 0 · ครบจริง
node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/status-stale"     # exit 1 · ทุก step done แต่มี stale
node "${CLAUDE_PLUGIN_ROOT}/scripts/status.mjs" --root "${CLAUDE_PLUGIN_ROOT}/scripts/fixtures/status-question"  # exit 2 · ทุก step done แต่คำถามยังค้าง
```

สอง fixture ท้ายมีไว้พิสูจน์ว่า **"ทุก step done" ไม่พอที่จะได้ `0`** — ถ้าวันหนึ่งมีคนแก้สคริปต์ให้นับแค่ step สองอันนี้จะแดงทันที

สัญญาของแต่ละ fixture อยู่ที่ `scripts/fixtures/EXPECTED.md`
